6

데이터 — 있는 것과 없는 것

절반 이상이 이미 있다

법인 회원 정보(member_corp)에 기관 페이지의 뼈대가 거의 다 들어 있다.

칸쓰임상태
org_name · org_name_en 목록과 상세의 기관명. 영문명 칸이 이미 있다 있음
promotion_reg_no 1층 배지의 근거. 이 칸이 비면 등재되지 않는다 있음
specialties진료과목 거르기 있음
address · website지역 거르기 · 상세 있음
org_type의료기관과 유치업체를 가른다 있음

없는 것 — 새 표 하나면 된다

member_corp 있음
  • PKmember_id
  • org_name / org_name_en
  • promotion_reg_no
  • specialties / address
medicheck_listing 설계
  • FKmember_id
  • listed — 등재 여부
  • source / source_url
  • region
  • verified_at / verified_by
  • reg_expires_at — 등록 만료일
  • languages — 지원 언어
  • intro_ko / intro_en
  • photo
  • updated_at — 마지막 갱신

회원 정보에 칸을 더하지 않고 표를 따로 둔다. 등재는 회원 자격과 별개이고 (3장), 한 표에 섞으면 그 구분이 코드 안에서 흐려진다. listed 를 별도 표의 칸으로 두면 회원이지만 등재되지 않은 상태가 자연스럽게 표현된다.

실제 자료가 들어오자 두 곳이 깨졌다 2026-08-18

지역을 주소에서 잘라 쓰던 것. 이 장은 지역 거르기를 address 로 한다고 정했고, 코드는 'Gangnam-gu, Seoul' 처럼 쉼표가 있다는 전제로 뒤쪽을 잘랐다. 서울시 자료는 '서울특별시 강남구 도산대로 119' 라 쉼표가 없다 — 주소 전체가 지역이 되어 지역 상자에 100개의 서로 다른 '지역'이 들어찼다. 넣는 쪽이 지역을 정하도록 region 칸을 뺐다.

영문명. 서울시 목록에 영문명이 없다. 협회가 로마자로 옮겨 적으면 기관이 쓰지 않는 이름을 협회가 지어낸 것이 된다 — 7장이 "기관이 직접 고친다"고 한 이유가 이것이다. org_name_en 의 NOT NULL 을 풀고, 없는 것은 없는 채로 뒀다. 화면은 국문명을 그대로 보여 준다.

확인한 사람과 날짜를 남긴다

verified_at · verified_by 가 배지 옆에 그대로 표시된다. 누가 언제 확인했는지 없는 인증은 인증이 아니다. 협회 시스템의 다른 곳에서도 같은 문제가 반복되고 있다 — 승인·확인 기록을 남기는 칸을 전체적으로 한 번에 정리하는 편이 낫다.

7

누가 최신으로 유지하나

이런 사이트가 죽는 이유는 늘 같다

정보가 낡는다. 기관 수십 곳을 사무국이 손으로 유지하면 반년 뒤 다 낡고, 낡은 순간 신뢰가 사라진다. 전화번호 하나가 틀리면 그 기관만 죽는 것이 아니라 사이트가 죽는다 — 해외 환자는 한 번 헛걸음하면 다시 오지 않는다.

기관이 직접 고치게 한다

협회에 회원 포털 계획이 이미 있다. 거기에 "우리 기관 페이지" 를 붙이면 기관이 스스로 최신 상태를 유지한다. 사무국이 대신 타이핑하는 구조로는 유지되지 않는다.

고칠 수 있는 것과 없는 것을 가른다

칸기관협회왜
소개문 · 사진 · 지원 언어 고칠 수 있다확인만 자기 정보이고, 자주 바뀐다
진료과목 · 주소 · 연락처 고칠 수 있다확인만 같은 이유
등록번호 · 확인 날짜 · 등재 여부 못 고친다협회만 기관이 자기 인증을 고칠 수 있으면 인증이 아니다

마지막 갱신일을 숨기지 않는다

목록과 상세에 마지막 갱신일을 그대로 보여 준다. 불편해 보이지만 반대다 — 날짜가 없으면 3년 된 정보와 어제 고친 정보가 똑같아 보인다. 날짜가 보이면 환자는 스스로 판단할 수 있고, 기관은 오래된 날짜가 부끄러워서 고친다.

오래 방치된 기관은 어떻게 하나

일정 기간 갱신이 없으면 기관에 알림을 보내고, 그래도 없으면 목록에서 내린다. 내리는 것이 가혹해 보이지만, 낡은 정보를 남겨 두는 쪽이 사이트 전체에 더 해롭다. 기간은 미결 — 1년이 무난해 보인다.

8

협회 시스템과의 관계

별도 사이트로 만든다

이유내용
대상이 다르다협회 홈페이지는 국내 회원·종사자용, 메디체크는 해외 환자용이다. 한 화면에 섞으면 양쪽 다 흐려진다
언어가 다르다협회 홈페이지는 한국어가 기준이고, 메디체크는 영어가 기준이다. 기본 언어가 다른 사이트를 하나로 묶으면 계속 어긋난다
읽히는 방식이 다르다협회 소개가 옆에 붙어 있으면 인증이 협회 홍보물로 읽힌다. 3장에서 지키려는 것과 정면으로 부딪친다

다만 데이터는 하나다

협회 홈페이지 메디체크 → 같은 서버 · 같은 DB ← 사무국 화면

기관 정보를 두 벌 관리하지 않는다. 사무국이 회원 화면에서 고친 것이 메디체크에 그대로 나오고, 기관이 포털에서 고친 것도 같은 곳에 들어간다. 사이트가 둘이라는 것은 화면이 둘이라는 뜻이지 시스템이 둘이라는 뜻이 아니다.

배포 방식은 아직 정하지 않는다

협회 홈페이지는 별도 저장소로 GitHub Pages 에 나간다 (도메인 지도). 메디체크를 같은 방식으로 할지, Java 가 직접 서빙할지는 미결이다. 다만 어느 쪽이든 API 는 같은 서버를 본다 — 허용 출처 목록에 메디체크 도메인을 더해야 하고, 그 계약은 기존 테스트가 지킨다.

9

미결과 위험

먼저 정해야 하는 것

항목왜 먼저인가정할 사람
도메인 · 상표 이름은 메디체크 코리아로 확정됐다(1장). 남은 것은 확보다 — 도메인과 상표를 조회하고, 막히면 후보를 다시 본다. 이름을 화면과 인쇄물에 쓰기 시작하기 전에 끝나야 한다 협회
미회신 기한과 조치 회신 주체는 기관 직접으로 정해졌다(5장). 남은 것은 며칠까지 안 오면 사무국이 개입하는가와, 반복 미회신을 어디까지 제재하는가다. 3영업일을 제안한다 협회
건당 수수료의 법적 가부 수익 모델은 인증 심사비로 정해졌다(12장). 다만 3단계에서 예약을 연결하며 건당 대가를 받게 되면 외국인환자 유치업 등록 문제가 붙는다. 3단계 설계 전에 법률 검토가 끝나야 한다 법률 검토
2층 심사 기준 1층으로 시작하되, 2층을 언제 어떤 기준으로 열지는 정해 둬야 기관들이 준비할 수 있다 협회
탈락한 후보 — 버리지 않고 남겨 둔다

도메인이나 상표가 막히면 여기서 다시 고른다. 셋 다 우열·효과 암시어를 피하고 Medical Korea 와 겹치지 않는다는 조건은 이미 통과한 이름들이다.

한글영문성격
케어 인 코리아Care in Korea 뜻이 즉시 읽히고 발음이 가장 쉽다. 다만 인증이 안 드러난다 — 그래서 밀렸다
케어패스 코리아CarePath Korea 환자 여정을 이름이 말한다. 15장을 앞세우는 전략이면 이쪽이 맞다
코리아 케어 얼라이언스Korea Care Alliance 주체가 협회임을 드러낸다. KMTPA 의 Association 과 결이 같고 Council 보다 과장이 덜하다

위험

위험어떻게 나타나나막는 법
인증 신뢰 붕괴 "돈 낸 곳만 올라간다"는 말이 한 번 퍼지면 회복이 안 된다 4장의 다섯 규칙. 특히 탈락 사례를 감추지 않는 것
정보 노후 반년이면 낡는다. 조용히 진행되어 아무도 눈치채지 못한다 기관 자율 갱신 + 갱신일 노출 + 방치 시 자동 하차 (7장)
빈 사이트 등재 기관이 열 곳뿐이면 검색할 값어치가 없다 공개 전에 최소 등재 수를 정하고 그때까지 열지 않는다
문의가 새는 것 해외에서 문의가 왔는데 아무도 답하지 않는다. 한 건이면 충분히 치명적이다 회신은 기관이 하되(5장) 전달 시각과 회신 시각을 남겨 사무국이 미회신만 본다. 기관에 넘겼다는 것으로 협회 책임이 끝나지 않는다
의료광고 규제 기관 소개문의 표현이 규제에 걸릴 수 있다 소개문은 기관이 쓰되 협회 확인 후 게시. 확인 항목을 목록으로 만들어 둔다
다음 문서

단계 · SaaS · 수익 · 언어는 10~14장이 이어받았고, 경첩이던 회신 주체가 풀렸다 — 기관이 직접 받는다(5장). 그래서 막혀 있던 문의 화면을 그릴 수 있게 됐고, 27~32장이 그것을 포함한 화면 문안을 맡는다.

남은 갈래는 인증 운영 규정이다 — 등재 신청 · 확인 · 만료 · 하차의 절차와 서식. 4장의 다섯 규칙은 무엇을 지킬지만 말하고 어떻게 지킬지는 아직 아무 데도 없다. 그 문서가 다음이다.
